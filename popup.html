Company Rater - AI Mode

Every search asks Google about "Companies per search" companies at once, in one structured question - fewer searches for the same list, which is both faster and lower-risk (fewer requests from your IP). If a search comes back with no answer at all it is reloaded once, and anything still unresolved is recorded as not rated so the run moves straight on to the next batch. Companies are never re-searched one at a time (that was far too slow); use "Retry not-rated rows" later to give them another go.
CSV columns: company name (required), plus any of: id, website, address, city, country. If a row has a website it is used to identify the company; if not, the website is looked up first. Either way the company then gets a 1-10 overall-performance rating with a one-line reason.
Concurrent tabs run that many batches at the same time, so 4 tabs × 5 companies per search works through 20 companies per round instead of 5. The tabs open in the background in your current window and are never brought to the front, so the run doesn't interrupt what you're doing - and it keeps working while the window is minimised or you're in another app. They close themselves when you press Stop.
Shorter delays and more concurrent tabs = faster, but both raise the chance of tripping a block (more tabs = more simultaneous traffic from one IP). 2-4 tabs is a sensible starting point; a run is staggered so the tabs don't all hit Google on the same instant. Concurrency can only be changed while the project is stopped.
